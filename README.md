# Тир-лист стартапов (full-stack)

Одностраничное приложение: раскладываешь стартапы по тирам S–F, прогресс сохраняется
на сервере и привязан к твоему GitHub-аккаунту.

- **Бэкенд:** Node.js + Express, сессии в cookie, OAuth 2.0 GitHub (`read:user`).
- **Хранилище:** JSON-файл `data/db.json` (без нативных сборок, ничего компилировать не нужно).
- **Фронтенд:** чистые HTML/CSS/JS, без сборщиков и CDN.

---

## 1. Что нужно установить

Только **Node.js 18.17+** (лучше 20 или 22) — проверьте:

```bash
node -v      # должно быть v18.17.0 или выше
npm -v
```

## 2. Создайте OAuth-приложение в GitHub

1. Откройте <https://github.com/settings/applications/new>
   (Settings → Developer settings → OAuth Apps → New OAuth App).
2. Заполните поля:

   | Поле | Значение |
   |---|---|
   | **Application name** | `Тир-лист стартапов (local)` — любое название |
   | **Homepage URL** | `http://localhost:3000` |
   | **Authorization callback URL** | `http://localhost:3000/auth/github/callback` |

3. Нажмите **Register application**.
4. Скопируйте **Client ID**.
5. Нажмите **Generate a new client secret** и сразу скопируйте секрет —
   GitHub показывает его только один раз.

> ⚠️ **Authorization callback URL** должен совпадать символ в символ с тем, что в `.env`
> (`GITHUB_CALLBACK_URL`). Любое расхождение — и GitHub отдаст `redirect_uri_mismatch`.
> Если смените порт (например, на 3001), поменяйте URL и здесь, и в `.env`.

## 3. Настройте окружение

```bash
cd startup-tier-list-fullstack
npm install
cp .env.example .env
```

Откройте `.env` и вставьте свои значения:

```ini
PORT=3000
SESSION_SECRET=<длинная случайная строка>
GITHUB_CLIENT_ID=<Client ID из шага 2>
GITHUB_CLIENT_SECRET=<Client secret из шага 2>
GITHUB_CALLBACK_URL=http://localhost:3000/auth/github/callback
DATA_FILE=./data/db.json
NODE_ENV=development
```

Сгенерировать `SESSION_SECRET`:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

## 4. Запустите

```bash
npm start
```

В терминале появится:

```
  Тир-лист стартапов запущен
  Откройте в браузере:  http://localhost:3000
```

Откройте <http://localhost:3000>, нажмите **«Войти через GitHub»**, разрешите доступ —
появится аватарка и ник, можно раскладывать стартапы.

Для разработки удобнее `npm run dev` — сервер сам перезапускается при правках.

### Быстрая проверка ключей GitHub

Если вход не срабатывает, можно не гадать — есть команда:

```bash
npm run check:github
```

Она делает один запрос к GitHub с заведомо неверным кодом и отвечает прямо: ключи верные
(`invalid_grant`), пара неверная (`incorrect_client_credentials`) или GitHub не знает такой
`client_id` (404 — самая частая причина: скопированный с ошибкой или стёртый Client ID,
либо созданное вместо OAuth App приложение типа GitHub App). Никакие права при этом
не запрашиваются и не выдаются.

## 5. Что было проверено

- Вход через GitHub: обмен `code` → `access_token` → `GET /user`, сессия в httpOnly-cookie,
  `state` защищает от CSRF.
- Прогресс сохраняется после каждого действия (`PUT /api/progress`) и **выживает** перезагрузку
  страницы, закрытие вкладки и перезапуск сервера (лежит в `data/db.json`).
- Механика: одна карточка за раз, кнопки S–F, drag&drop мышью, перетаскивание пальцем на телефоне,
  «Пропустить», «Отменить последнее», меню чипа (перенести/убрать), экран «Готово»,
  счётчик «Осталось: N из 59».
- Запросы к API без сессии возвращают 401, сервер валидирует тело запроса
  (чужая компания или неизвестный тир не пройдут).

## Деплой в интернет (чтобы кинуть ссылку коллегам)

### Вариант 1. Render — бесплатно, без карты, постоянная ссылка (рекомендую)

В репозитории уже лежит файл `render.yaml`, так что всё разворачивается «в один клик»:

1. Зарегистрируйтесь на <https://render.com> (можно войти через GitHub).
2. **New → Blueprint** → выберите репозиторий `startup-tier-list` → **Apply**.
3. Render спросит две переменные (они помечены в `render.yaml` как `sync: false`):
   `GITHUB_CLIENT_ID` и `GITHUB_CLIENT_SECRET` — возьмите из настроек OAuth App.
   `NODE_ENV=production` и `SESSION_SECRET` Render подставит сам.
4. В настройках **OAuth App** на GitHub добавьте callback вашего сервиса:
   `https://<имя-сервиса>.onrender.com/auth/github/callback`
   Точный адрес Render печатает в логе запуска (строка `Callback URL для GitHub OAuth App`).
   Если поле принимает только один адрес — на время демо замените существующий, локальный вернёте потом.
5. **Проверьте настройки на самом хостинге** (без входа): откройте `https://<имя-сервиса>.onrender.com/auth/status`.
   В ответе `clientId` и `callbackUrl` — это ровно то, что сервер отправляет в GitHub. Значение `callbackUrl`
   должно посимвольно совпадать со строкой в «Authorization callback URL» OAuth App.
6. Через 2–3 минуты сервис поднимется: открывайте `https://<имя-сервиса>.onrender.com` и отправляйте ссылку коллегам.

Что нужно знать про бесплатный план:
- сервис засыпает после ~15 минут простоя, первый заход занимает 30–60 секунд;
- диск эфемерный: после перезапуска или редеплоя прогресс из `data/db.json` обнуляется
  (человек просто войдёт заново и начнёт новый тир-лист);
- если нужна гарантированная сохранность — добавьте платный диск (Render → Disks) или скажите мне,
  и я заменю JSON-файл на бесплатную Postgres/Redis (весь доступ к данным изолирован в `src/db.js`).

### Вариант 2. Любой хостинг с Node.js (Railway, Koyeb, Fly.io, VPS)

Сборка не нужна, достаточно переменных окружения:

| Переменная | Значение |
|---|---|
| `NODE_ENV` | `production` |
| `PORT` | обычно задаёт сам хостинг |
| `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET` | из настроек OAuth App |
| `SESSION_SECRET` | длинная случайная строка |
| `PUBLIC_URL` | `https://ваш-домен` — из него соберётся callback |

Команды: установка — `npm ci`, запуск — `npm start`, проверка живости — `/healthz`.
И не забудьте добавить `https://ваш-домен/auth/github/callback` в OAuth App.

### Вариант 3. Ссылка без хостинга (живёт, пока включён ваш Mac)

В VS Code откройте панель **Ports** → **Forward a Port** → `3000` → правый клик →
**Port Visibility: Public**. Получите ссылку вида `https://xxxx-3000.app.github.dev` —
её тоже нужно добавить в callback URL OAuth App. Прогресс при этом хранится у вас на диске.

## Структура проекта

```
startup-tier-list-fullstack/
├── server.js               # точка входа: express, сессии, статика, обработка ошибок
├── package.json
├── .env.example            # шаблон настроек (сам .env не коммитится)
├── .gitignore
├── src/
│   ├── config.js           # все настройки из .env в одном месте
│   ├── db.js               # JSON-хранилище (атомарная запись): пользователи, прогресс, сессии
│   ├── session-store.js    # хранилище сессий поверх db.json: вход не слетает после перезапуска
│   ├── auth.js             # OAuth 2.0 GitHub: /auth/github, callback, /auth/logout
│   ├── api.js              # /api/me, /api/companies, /api/progress (+ валидация)
│   └── data/companies.js   # список стартапов и описание тиров
├── public/
│   ├── index.html          # разметка экранов: загрузка, вход, игра
│   ├── styles.css          # тёмная тема, 7 цветных полос, адаптив от 380px
│   ├── app.js              # вся клиентская логика
│   └── 404.html
└── data/db.json            # создаётся автоматически (прогресс пользователей)
```

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/auth/github` | редирект на GitHub для входа |
| GET | `/auth/github/callback` | принимает `code`, создаёт сессию |
| GET | `/auth/status` | самодиагностика без входа: какой `client_id` и какой callback реально использует сервер (секреты не показывает) |
| POST | `/auth/logout` | выход (удаляет сессию) |
| GET | `/api/me` | текущий пользователь (401, если не вошёл) |
| GET | `/api/companies` | список стартапов и тиры |
| GET | `/api/progress` | сохранённый прогресс |
| PUT | `/api/progress` | сохранить прогресс (полное состояние) |
| GET | `/healthz` | проверка живости сервера |

Состояние прогресса, которое лежит в базе:

```json
{
  "queue": ["Stripe", "OpenAI"],
  "current": "Revolut",
  "assignments": { "Anthropic": "S", "Binance": "F" },
  "done": false,
  "updatedAt": "2026-09-12T17:00:00.000Z"
}
```

## Частые проблемы

| Симптом | Причина и решение |
|---|---|
| `redirect_uri_mismatch` | **Authorization callback URL** в OAuth App не совпадает с `GITHUB_CALLBACK_URL`. Нужно ровно `http://localhost:3000/auth/github/callback`. |
| `incorrect_client_credentials` | Неверный `GITHUB_CLIENT_SECRET`. Сгенерируйте новый («Generate a new client secret») и обновите `.env` (или переменную окружения на хостинге). После правки `.env` сервер нужно перезапустить. |
| GitHub отдаёт **404** при нажатии «Войти через GitHub» | GitHub не знает такой `client_id` (для существующего приложения он отвечает иначе — проверено). Откройте `https://<ваш-сервис>/auth/status?probe=1`: поле `githubProbe.verdict` скажет прямо — `client_id_unknown`, `client_ok_secret_wrong` или `credentials_ok`. Если `client_id_unknown` — скопируйте Client ID заново кнопкой Copy из настроек приложения и обновите переменную на хостинге. Приложение дополнительно подстрахуется само: если в переменной окружения опечатка `0` вместо `O` (классика при копировании), оно возьмёт встроенный Client ID (он не секрет) и напишет об этом в лог, а в `/auth/status` покажет `"clientIdSource": "built-in (исправлена опечатка 0/O)"`. |
| `redirect_uri_mismatch` | Значение `callbackUrl` из `/auth/status` должно **посимвольно** совпадать со строкой в «Authorization callback URL» OAuth App. Типичная ошибка — указать `https://onrender.com` (это сайт Render) вместо `https://<имя-сервиса>.onrender.com`. |
| «GitHub не признал client_id (ответ 404)» | GitHub не знает такой `client_id`. Скопируйте его заново из настроек OAuth App (кнопкой Copy, не перепечатывая руками) и проверьте, что создано именно **OAuth App**, а не GitHub App. Проверить: `npm run check:github`. |
| `Не хватает переменных окружения: ...` | Нет `.env` или значения пустые. Смотрите шаг 3. |
| `Порт 3000 уже занят` | Закройте прошлый запуск или смените `PORT` в `.env` **и** callback URL в OAuth App. |
| Вход не завершается, ошибок в консоли нет | Проверьте, что машина может достучаться до `api.github.com` (файрвол / корпоративный прокси). |
| Хочу начать всё заново | Кнопка **«Сбросить всё»** в приложении. Полный сброс: удалить `data/db.json` при остановленном сервере. |
| Данные не сохраняются | Смотрите индикатор в шапке («не сохранилось» + сообщение) и права на запись в папку проекта. |

## Что важно знать про продакшн

Локально всё работает как есть, но перед выкладкой в интернет нужно:

1. **Хранилище сессий.** Сессии лежат в `data/db.json` (`src/session-store.js`) и переживают
   перезапуск сервера. Этого достаточно для одного процесса; если инстансов станет несколько,
   замените `store: new JsonSessionStore()` в `server.js` на Redis/SQLite — строчка одна.
2. **HTTPS.** Поставьте `NODE_ENV=production` (тогда cookie станет `secure`, а `trust proxy`
   включится) и запускайте за HTTPS-прокси.
3. **Callback URL.** Замените `GITHUB_CALLBACK_URL` и URL в OAuth App на боевой домен.
4. **Секреты.** `SESSION_SECRET` и `GITHUB_CLIENT_SECRET` — только через переменные окружения.
5. **Хранилище данных.** JSON-файла хватает на небольшой проект; вся работа с данными
   изолирована в `src/db.js`, поэтому замена на SQLite/Postgres не затронет остальной код.

## Заметки по деталям

- Access token GitHub используется один раз — для чтения профиля — и нигде не сохраняется.
- В `data/db.json` лежат только публичные поля профиля (id, login, имя, аватар, ссылка).
- «Отменить последнее» работает в рамках открытой вкладки: на сервере хранится только актуальное
  состояние. Если нужно, чтобы отмена переживала перезагрузку — скажите, вынесу стек в базу.
- Список стартапов живёт в `src/data/companies.js`. Если его поменять, сохранённый прогресс
  подстроится сам: исчезнувшие компании уйдут, новые встанут в конец очереди.
